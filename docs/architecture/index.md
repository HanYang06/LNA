# 架构文档索引

> `docs/architecture/*.md` 是设计事实来源。两条前提：
> **① 每篇都标了状态；② 与[路线图](../roadmap/1.x.md)冲突时以路线图为准**。

## 权威顺序

```text
路线图  >  设计  >  代码
```

- **路线图管「要什么」**：做什么、按哪套设计、落在哪个版本（[1.x.md](../roadmap/1.x.md)）。
- **设计管「是什么、为什么」**：`docs/architecture/` 下各篇。
- **代码管「现在是什么」**：现状的唯一证据。
- 三者冲突时**改下层**；推翻上层只有两种动作——**新增条目**，或**撤回条目的 `决策状态`**
  （`已定` → `待裁` / `已废弃`）。条目只增不减、版本号只增不减。

## 逐篇状态

| 文档 | 权威范围 | 与代码的对应 | 状态 |
|---|---|---|---|
| [设计](design.md) | 形态、私有语言、A / B / C、达成路径、待定 | **无代码**（构想阶段） | 现行 |

> 标「草案」的篇目表示方向已定、部分未实现；标「预留」的表示只有方向。
> **凡标「预留 / 草案 / 待定」的内容，不作为实现依据。**
