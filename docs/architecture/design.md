# LNA 设计

> 配套[架构索引](index.md)与 [README.md](../../README.md)。记录 LNA 的设计共识与开放问题。
>
> **状态**：构想阶段。本文档区分「**已定**」（当前设计决策）与「**待定**」（交由实验回答）。
> **原则**：做一步看一步；能定的定，定不下来的不硬定。

## 0. 一句话

模型与模型之间，应当有一门**私有的、通用的语言**；模型本身不应是单体大模型。这门语言是整套框架成立的前提。

---

## 1. 形态（已定）

不是单体大模型，而是由 **N 个独立的小型专家模型**组成的**联合网络**；每个专家都是独立的小模型。

**为什么是 N 个专家**
- 让一个网络去学**所有**问题，权重会不停偏移、拉扯、互相干扰，最终也许"还不错"，但未必好；而让它在**一件事**上绝对专精，**参数量很小**就能做到真正意义上的完全专精。
- 封闭词表的价值正在于此：它把每个专家的输入 / 输出空间**约束在一个小而封闭的符号集**里，使小参数量也能"足够专、足够精"。

## 2. 为什么需要一门私有语言（已定）

联合网络一旦成立，就必须为它制定一套**通用语言**，否则会出现根本问题——**语言不同步**。
- 直接沿用自然语言：自然语言描述本身带**歧义**。
- 要的是**消歧义**，而消歧义的载体正是词本身。

## 3. 语言的形式（已定）

一个"词" = **ID + 向量**，二者分工：
- **ID**：寻址、版本、路由。离散、封闭、固定宽度，基础锁定、增量向后扩展。
- **向量**：可导性与带宽。它是**可微把手**——纯 ID 不可导，梯度传不过去，专家就没法训。

关键点：
- **向量表是共享的、外部的、全局唯一的**：全体模型参照**同一张**表——**只有一份，就没有「两份表对不上」**，故不需要两两对齐。
- **双向奔赴，不是单向适应**：**ID 随便编**（它只是编号，含义不靠它），含义长在**向量**上——所以不是「模型去适应一张莫名其妙的随机表」，
  而是**模型与表互相塑造**；N 个模型共同注入含义，即**多向奔赴**。**防漂移不靠冻结**，靠三样：**全局唯一一份** ＋ **门控** ＋ **固化点（版本）**。
- **「冻结」指固化后的版本**（固化那一刻锁死）；表如何承接梯度由**梯度下降分析**回答。
- **封闭词表**：基础固定即锁定，后续增量向后扩展（可版本化）。**这张表本身就是语言版本号。**
- **组合优于增量**：表达力靠**组合**（长词序列），不靠堆词——所以词表要**小**（`v_max` 起步 1024）。
- **根本挑战：模态统一性**——当一门语言能同时描述**所有模态**时，它才有价值。（参照：自然语言用足够多的字就能描述图片 / 音频 / 视频；能力是有的，难点在"怎么做"。）

### 含义与梯度下降分析（已定）

**含义不是随机向量自带的**——随机生成一个向量，不代表它"真的带有含义"。**含义是模型赋予的，体现在向量上**；
要**从模型的视角**判断它到底**真的带有含义，还是假的**（真 ⇒ 经得起**坍缩检测**与**组合性探针**）。

**方法论：不硬逼梯度下降，但要分析一遍。** 模型本身要做梯度下降，我们这边也对这张表做**梯度下降分析**，
看它对梯度有没有表现——说白了，**这相当于在训练一个「幽灵模型」**：有参数、挨梯度、被优化，像模型；
却**没有自己的前向**，只活在别的模型引用它的时候（见术语表）。

### 语言参数（已定）

**原则：能当超参的都当超参。** 下面这些量**都进配置**（hydra，落仓库根 `configs/`），
先给起步值、**实测好用再固化**——语言本身也是炼丹出来的。

| 量 | 起步值 | 说明 |
|---|---|---|
| ID | 32 位无符号，hex 表示（8 位 hex） | 范围极广，精确寻址、可**划范围**分段 |
| 向量维度 D | 128 | 可配 |
| 向量精度 | float32 | 参照系要精确、可复现 |
| 向量类型 | **浮点** | 必须可导（纯整数梯度传不过去） |
| 初始化 | **随机** | 无偏、词间天然可分；固定 seed 保可复现 |
| 词表上限 `v_max` | 起步 **1024**（2^10；前 64 留控制符） | **组合优于增量 → 数字不能多**；进配置，可试 256 / 512 / 2048 |
| 序列长度 | `L_max` = 64，变长 | 门控保证均值不顶格 |
| 序列评判 | 按**词 ID** 计 | ID 是主体，向量只是载体 |
| 注意力 | **上**（已定）——`n_heads` = 4、`d_head` = D / `n_heads` = 32 | 不上注意力，语言表达缺得多；**是否 causal 待定** |

**词表的性质**：像 **tokenizer**——**全局唯一、共享、外部**的参照系，伴随训练全程；哪次实验的表好用，
就把那一版**固化**成语言版本（**固化即冻结**）。

## 4. 驾驭架构与 A / B / C 的角色（已定）

整套架构的总名是 **驾驭架构**，核心是**驾驭**。它由**三个支柱**与一层**横切基础设施**构成：

- **支柱① 模型**：它就是**模型**，**角色无关**。
- **支柱② 调度核心**：① **加载模型**；② 按数据决定**往哪路由**；③ **声明式编排**（Python → JS / YML，见下）。
- **支柱③ 训练**：一套训练框架，**基于一套数据一次批量训出 N 个专家**（不是一个个盯）。
- **横切基础设施**：数据加载 / 硬件监控 / 训练报告。

**硬约束：模型是模型，架构是架构。** 模型**不带角色**；A / B / C 是**调度核心在运行时分配的角色**，
不是模型的层、更不写进模型代码——**写死就失去多模型编排的能力**，做编排就得改代码。

### 调度核心的形态（已定）

**不搞 DSL**——直接走 Python：调度核心提供一套**声明 API**，用普通 Python 的写法声明
「哪个层用哪个模型、怎么用、进去什么语言、出来什么语言」。写起来与日常 Python 开发无异。

区别在**运行之后**：它**不直接让框架跑起来**，而是**代码生成两套文件**——
- **JS**：机器生成、给机器执行，**不给人看**；
- **YML**：给人看的「加糖」描述（JSON 生成出来太啰嗦，不便读）。

在此之上，A / B / C 是三个**角色**：
- **A / C**：对外换能器。把外界的语言或模态**翻译成内部语言**，以及把**内部语言翻译回去**。
  初期二者**同构**（为了能验证），**未来不同构**。
- **B**：**N 个专家网络**（不是一个网络），每个专家是独立小模型，只讲内部语言。

## 5. 达成路径（已定）

- 这是一个**炼丹**过程，不可能一蹴而就，需要持续迭代。
- 训练难度未必大，重心更多在**验证**。
- 方法：**分而治之，最后统合**。

### 训练路线
- **Phase 1 — A / C 点对点（同构）联合训练**：文本 → A → 内部码 → C → 文本；把还原出的文本与原文本**比对一致性**。纯炼丹。
- **Phase 2 — 引入 B**：A / C 训到一定程度后加入 B，三方一起炼。
- **Phase 3 — A / B / C 联合，并加宽 B**：B 内新增多个角色 / 专家，继续炼。
- **Phase 4 — 重新聚合**：炼到接近确定后，把这些模型重新聚合，产出**最基础的语言模型**。

### 防坍缩门控（已定要加）
起点只有 A、C 两个模型时，极可能学成**平凡双射查表**（token X → 向量 Y → token X）：用了词表，却没造出语言。对策——**逐条输出打分，从生成侧控制**：
1. **编码长度调控**：不能顶格，也不能极致压缩，压到一个合理阈值（≈ 率失真 / 信息瓶颈的权衡）。
2. **信息熵**：不算熵，必然坍缩（≈ 熵正则，防码本 / 后验塌缩）。
3. **组合性探针**：防**整体式编码**——每个输入各给一个独一无二、不可拆的码（熵漂亮、长度合理，但零可重组，本质仍是查表）。判据：内部码的子段是否独立有意义、能否挪到别的输入里重组。

### 验证判据
- **坍缩检测**：换一批**没见过**的文本对，看往返一致性是否立刻崩。崩 → 查表；没崩 → 才算有语言。
- **泛化阈值**：把"新角色的学习难度"操作化为「达到 X% 往返一致率所需的梯度步数」，降到 baseline 以下即泛化成功。
- **权重对比**：A、C 同构，故可比。目标是找**共通结构**（有结构 = 语言有几何；无结构 = 纯查表）；找不到就重练。

## 6. 待定（交由实验回答，非现在能拍板）

- **B 进来后具体干什么**：中继 A→B→C / 第三方学习者（"小李"）/ 专才。它决定 Phase 2 的损失函数。
  - 附带一个坑：**B 一旦做事，纯往返损失即失效**（输出不再等于输入，"恢复原文"当不了损失）。
- **"重新聚合"的具体机制**：蒸馏 / 权重平均 / 加路由。先靠找共通性；实在找不到就重练。
- 词表的具体内容；模态统一性的具体实现；A / B / C 内部子部分的划分。
- **【假设 · 概念车】幽灵模型 ＋ 推演结构 = 内部语言自己的本体模型**：词表给**词法**（静态：词**是**什么），
  推演结构给**动力学 / 句法-语义**（动态：词**怎么演**），合起来 = **一门语言自己变成可运行的模型**——
  幽灵「显形」，从**名词**变**动词**。这就是 Phase 4「最基础的语言模型」的**内核**。
  ⚠ **风险**：只被内部语言自身一致性塑造，会**自洽但空洞**——必须始终挂在 **A / C 的外部锚**上，否则是梦呓。
  （**假设，未验证，不作实现依据**。）
